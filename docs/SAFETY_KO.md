# 안전 설계

로봇은 바퀴로 움직이고 팔에는 끼일 곳이 있다. 이 앱은 "놓으면 멈춘다, 저절로 다시 움직이지 않는다"를 기본으로 한다. 로봇 쪽 규칙(Protocol v3: 채널별 중립 확인, watchdog 0.4초, lease 1초, 비상정지 latch)은 그대로 따르고, 앱이 그 위에 제한을 더한다.

## 규칙

1. **비상정지는 한 번에.** B, Space, 화면의 빨간 버튼(손가락이 닿는 순간 발동). 창 포커스가 없어도 B는 듣는다. 로봇이 ACK를 줄 때까지 50 ms마다 다시 보낸다(조종 스레드가 혼자 처리하므로 화면이 멈춰도 계속된다).
2. **해제는 길게.** View 또는 화면 버튼을 0.8초. 해제한 뒤에도 차체는 스틱을 놓았다가 다시 밀어야, 팔은 LB를 다시 눌러야 움직인다.
3. **팔은 데드맨.** LB(또는 Shift)를 누르는 동안만 팔 채널이 활성이다. 터치로 켜 둔 팔은 60초 무입력이면 꺼진다.
4. **팔 목표는 점프하지 않는다.** 스틱·터치 그림·숫자 어느 입력이든 손끝 0.15 m/s, pitch 0.6 rad/s, 그리퍼 0.8/s 상한으로 목표에 다가간다.
5. **닿지 않는 곳으로 앞서 나가지 않는다.** 로봇과 같은 목표 보정 규칙(`TargetProjector`)으로 앱에서 먼저 보정하고, 로봇이 보정했다고 알리면 앱 목표를 로봇이 실제로 쓰는 목표로 되돌린다. 이때 짧게 진동한다.
6. **포커스를 잃으면 중립.** 다른 창으로 가거나 최소화하면 입력을 모두 내리고 팔을 끈다. 돌아와도 저절로 다시 움직이지 않는다.
7. **입력이 끊기면 중립.** 화면 스레드가 0.3초 넘게 입력을 넘기지 않으면 조종 스레드가 중립을 보낸다. 앱이 통째로 죽으면 로봇 watchdog(0.4초)이 차체를 세우고 팔을 그 자리에 둔다.
8. **패드가 빠지면 중립.** 다시 꽂히면 스틱이 가운데로 돌아온 뒤에만 입력을 받는다.
9. **조종 중 화면이 꺼지지 않게** 연결된 동안 `SetThreadExecutionState`로 잠자기를 막는다.
10. **한 기기에 한 조종기.** 같은 Ally에서 두 번 실행하면 두 번째는 뜨지 않는다.
11. **로봇 전체 해제**(`/armpi/reset_estop`)는 길게 누름 + 확인 두 단계. 게임패드로는 할 수 없다.

## 실패 처리

| 상황 | 앱 동작 | 표시 |
|---|---|---|
| ACK 0.3초 없음, watchdog timeout | 의도를 유지하면 중립 → 확인 → 활성을 스스로 다시 밟음 | "통신 끊김" 알림, 진동 |
| 다른 조종기가 조종 중(not_owner), fault, 비상정지 | 강한 차단: 사용자가 손을 뗐다 다시 해야 재개 | 상단 칩 빨강 |
| 팔 목표 보정·거부 | 목표를 보정값 또는 마지막 수락값으로 | 노랑 알림, 약한 진동 |
| rosbridge 끊김 | 2초마다 다시 연결. UDP 조종은 계속 | "rosbridge 없음" |
| 카메라 끊김 | 2초마다 다시 연결 | "영상 없음" |
| 앱 종료 | 중립 2개 + disconnect, 진동 0, 잠자기 방지 해제, 설정 저장 | — |

## 실제 로봇 첫 시험 전에

- 바퀴를 띄운다(받침). 팔이 닿는 범위를 비운다. 전원 스위치를 손 가까이에 둔다.
- 속도 상한 10–30 %로 시작한다. 화면 비상정지는 소프트웨어 정지라 로봇 프로그램이 멈추면 듣지 않는다.
- 비상정지가 걸려도 팔은 토크를 유지한 채 선다(떨어지지 않게 하는 로봇 규칙).
